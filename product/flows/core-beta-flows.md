# Core Beta flow contracts

## `FLOW-ACTIVATE-001` — New couple activation

`First open → Goal → Minimal setup → Starter Rhythm → Invite → Web Join → First shared interaction → Human response`

The activation is not complete at account creation or invite acceptance. It reaches product value only when the first bilateral human-response event occurs.

## `FLOW-RECEIVE-001` — Receiving daily loop

`Open Today → understand priority → act or adjust → wait → receive human response`

Today must support Complete, Need to Discuss, Request New Time and Can't Do without forcing a detail page for basic understanding.

## `FLOW-ATTENTION-001` — Direction-giving daily loop

`Open Attention → see human-response priorities → respond inline → clear meaningful work`

Proposal inbox is excluded. Human response must remain quick but explicit.

## `FLOW-ADJUST-001` — Reality adjustment

`Active occurrence → Discuss / Request New Time / Can't Do → partner resolution → Continue / Adjust / Reschedule / Excuse / Cancel`

These paths do not create an automatic miss. Past due enters Needs Review.

## `FLOW-PAUSE-001` — Pause and return

`Active → Pause → no new recurring backlog → Resume → same / lighter / adjust`

Either member may pause. Return does not require completing paused-period occurrences.

## `FLOW-EXIT-001` — Leave and block

Leave requires no approval. Block cuts future access, invitation/reconnection and newly initiated delivery. Stale routes resolve to a neutral safe state.

## `FLOW-WEEKLY-001` — D7 reflection

`Recent real relationship events → connected/acknowledged moments → Keep / Adjust / Pause → next rhythm`

No score and no complex memory object are exposed in Core Beta.

## Cross-flow platform rule

Flutter Android and Flutter Web share the same server business truth. Web is a full companion for Join, Today/Attention, Complete/Acknowledge, Check-in and History—not a landing page. Platform UI may differ where browser history, session, push, storage or lifecycle require it.
