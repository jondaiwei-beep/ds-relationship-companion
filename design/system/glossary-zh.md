# 中文术语表

这个 app 的措辞不是普通 UI 文案。`Expectation`、`Acknowledgement`、`Dynamic`
这些是产品的核心概念（`product/00-overview.md` 定义了四个关系信号），译错一个
词，整个体验的含义就变了。这份表定死这些词的中文，任何界面文案都必须用表里的
译法，不得临时另译。

## 判据

三条，按优先级：

1. **说人话。** 用户不是产品经理。看到一个词要能立刻知道是什么意思，而不是先
   猜它是不是术语。
2. **系统的口吻不带评判。** 这个产品的红线之一是"调整不是失败"（red line
   #3）。**系统自己说话时**不用"失败/违约/逾期"这类把关系变成 KPI 的词。
   但"服从 / 惩罚 / 跪 / 项圈 / 主人"是这些用户自己的词汇 —— 2026-09-02 起
   **解除全部内容限制**（owner 决定），它们在内容、约定、后果、两个人互相说
   的话里正常出现。之前禁用它们的结果是产品读起来像通用情侣 app。
3. **系统不冒充人。** 红线 #1：系统绝不以伴侣的口吻说话。所以凡是描述"对方做
   了什么"的词，中文必须能看出主语是人。

4. **不回避这段关系本身。** 前三条约束的是**系统**的口吻 —— 系统不评分、不惩
   罚、不要求服从。但它们不约束**两个人之间**的措辞。这个产品的定义是"给自愿
   的成年 D/s 伴侣用"，一方给方向、一方接受方向是他们自己约定好的前提。把每
   句话都软化成"想请对方做的事"，等于假装这个前提不存在 —— 用户会觉得这是个
   通用情侣 app，而不是为他们做的。
   `REQ-TRUST-001` 只要求**登录前**的界面用中性语言；登录之后没有这条要求，
   之前的中性语气是执行时漏进来的，不是需求。

## 核心概念

| 英文 | 中文 | 为什么 |
|---|---|---|
| Dynamic | 关系 | 不译"动态"——那是朋友圈那个动态。这个词指两个人之间正在进行的这段关系本身。界面上多数时候说"你们的关系"。 |
| Expectation | 约定 / 交代的事 | **不译"任务"**，也**不再译"心意"**。产品是给 D/s 伴侣用的，两个人已经约好一方给方向、一方接受方向 —— "心意"把这层关系抹掉了，读起来像普通情侣的贴心提醒。"约定"点明这是双方先谈好的，"交代的事"点明是谁对谁说的。两者都不带派工感，但也不假装这只是善意。 |
| Ritual | 日常 | 不译"仪式"——中文的"仪式"太重、太宗教。这里指每天重复的小事。 |
| Occurrence | 今天这一件 | 一个 Expectation 在某一天的具体实例。界面上几乎不出现这个词，出现时就说"今天这件事"。 |
| Acknowledgement | 回应 | **不译"确认"**——"确认"是签收，是流程动作。这里是一个人看见了另一个人做的事并且回话了，是关系动作。 |
| Adjustment | 商量 | **不译"调整申请"**。红线 #3：这是正常的路，不是异常流程。"商量"在中文里天然不带失败感。 |
| Check-in | 说说今天 | 不译"打卡"——打卡是考勤。这里是说说自己今天怎么样。 |
| Structure | 相处方式 | 不译"结构"——太工程了。指这两个人约定的相处节奏和分工。 |
| Presence | 在 | "对方在"，不是"在线"。这个产品刻意不做在线状态。 |

## 动作

| 英文 | 中文 | 为什么 |
|---|---|---|
| Complete | 做好了 | **不译"完成任务"**。"做好了"是对人说的，"完成"是对系统说的。 |
| Discuss | 想聊聊 | 不是"申请讨论"。 |
| New time | 换个时间 | 不是"改期申请"。 |
| Can't do | 这次做不到 | **关键**。不能译"无法完成"或"失败"——加"这次"是因为红线 #3 说明这不是关于这个人的判断，是关于这一次的事实。 |
| Withdraw | 算了，收回 | 提请求的人自己撤回。不是"取消申请"。 |
| Pause | 暂停 | 保留原词，中文语感一致。 |
| Resume | 回来 | 不译"恢复"——"恢复"像系统状态。"回来"是对人说的。 |
| Leave | 离开 | |
| Block | 拉黑 | 中文用户的既有词，不必新造。 |

## 状态

| 英文 | 中文 | 为什么 |
|---|---|---|
| Waiting for a human response | 等对方回应 | 强调"人"，不是"待审核"。 |
| Being discussed | 在聊这件事 | 不是"讨论中"。 |
| Excused | 这次不用了 | **不译"已豁免"**——豁免暗示本来有罪。 |
| Cancelled | 取消了 | |
| Needs review | 过时间了，看一眼 | **不译"逾期"**。产品明确：过期只是提醒去看，不是罚分（"Past due is only ever a prompt to look, never a penalty"）。 |
| Paused | 暂停中 | |
| Ended | 已结束 | |

## 绝对不能出现的词

这些词会把产品变成它刻意不做的东西（见 `product/00-overview.md` 的 Non-goals）：

- **任务、KPI、绩效、考核、打卡、签到** —— 这不是任务管理工具
- **失败、违约、未达标、扣分、评分、连续天数** —— 没有合规打分，没有强制连击
- **服从、惩罚、奖励、调教** —— 系统不做剧本，不自动奖惩
- **审核、批准、驳回、申请** —— 商量不是审批流程。红线：绝不能让"提出请求"
  读起来像"请求批准"
- **确认收到、已读** —— 回应是一个人写的话，不是回执

## 一致性

- 第二人称用「你」，不用「您」。这是两个亲近的人之间的产品，「您」会把距离拉开。
- 伴侣的名字直接用服务端给的 displayName，不加「先生/女士」。
- 空状态不说「暂无数据」——说清楚为什么是空的，以及这不是谁的问题。
